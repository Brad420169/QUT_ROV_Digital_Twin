# Installation and running

This covers cloning, ROS Jazzy, tether networking, Pixhawk/MAVROS, camera video,
camera SSH keys, gimbal dependencies, Stonefish and the digital twin.

Use **Ubuntu 24.04 Desktop**, internet and an account with administrator access.
Run the scripts as your normal desktop user, without `sudo` in front of `bash`.
They request administrator access when required.

All three stages use **one checkout** at `~/Desktop/ROV_and_DT_ws`:

1. Install the real ROV software.
2. Connect and configure the real ROV hardware.
3. Install Stonefish, its ROS 2 wrapper and the DT simulation.

The repository already contains both real and simulated vehicle software. Clone
`QUT_ROV_Digital_Twin`, not the separate `Real_ROV_Control` repository. This
repository is itself a ROS workspace; do not clone it inside another `src/` folder.

## Physical ROV: Install the software once

Ensure Git is installed
```bash
sudo apt update && sudo apt install -y git
```

Clone the repository and run the software installer:

```bash
mkdir -p ~/Desktop
git clone https://github.com/Brad420169/QUT_ROV_Digital_Twin.git ~/Desktop/ROV_and_DT_ws
cd ~/Desktop/ROV_and_DT_ws
bash src/stonefish_qut_rov/setup_scripts/install_software.sh
```
If you already have this checkout, use its existing location instead of cloning
again. The scripts determine the workspace from their own location, so a different
folder name or a Desktop symlink works too. Substitute that location for
`~/Desktop/ROV_and_DT_ws` in subsequent commands.

Software installation requires internet, but does not require the ROV or tether
to be connected. Use a fresh terminal outside a Python virtual environment or Conda.

The installer installs:
- ROS 2 Jazzy ROS Base.
- MAVROS and its GeographicLib datasets (connects ROS to the Pixhawk using MAVLink).
- Joystick support.
- ROS launch/message/transform packages.
- NumPy.
- OpenCV.
- Matplotlib.
- Tkinter (provides the graphical launcher interface).
- Pexpect (automates interactions with command-line programs, including SSH sessions).
- OpenSSH (provides remote access to the camera for gimbal control and temperature readings).
- The ARM cross compiler (builds the gimbal helper on the laptop so it can run on the camera’s ARM processor).
- Colcon/ament build and test tools (builds the ROS workspace and supports automated testing).
- NetworkManager and desktop utilities (configures the tether’s Ethernet connection and creates desktop and application-menu shortcuts).
It builds this workspace's `stonefish_qut_rov` package without requiring Stonefish
and creates **ROV** shortcuts on the desktop and in the applications menu.
The GUI contains real and simulation options; the simulation option becomes
usable after the DT installation in stage 3.

## Connect and set up the hardware

1. **Power the ROV and camera.** Ensure the kill switch is in its operating position. Connect the ROV’s tether to your PC/laptop through the FathomX Interface and Ethernet adapter.

2. **Keep internet connected through Wi-Fi**, then open a terminal and run:

   ```bash
   cd ~/Desktop/ROV_and_DT_ws
   bash src/stonefish_qut_rov/setup_scripts/setuphardware.sh
   ```

3. **Select the Ethernet adapter if prompted.** A single adapter is selected automatically. If several are detected, enter the number corresponding to the adapter connected to the ROV.

4. **Enter your Ubuntu login password if requested.** This allows the script to configure Ethernet. Nothing appears while typing; press **Enter** when finished.

   The script creates and activates the **Real_ROV_Tether** connection. Success messages confirm that the laptop is configured for both the vehicle network (`192.168.2.1/24`) and camera network (`192.168.144.10/24`). Wi-Fi remains the default internet connection.

5. **Choose whether to protect your SSH key with a passphrase.** If a new key is needed, you will see:

   ```text
   Enter passphrase (empty for no passphrase):
   Enter same passphrase again:
   ```

   This is an optional password protecting the SSH private key on your laptop—it is **not the camera password**.

   - **Without a passphrase:** press **Enter twice**. This allows unattended access, but anyone who obtains the private-key file could use it.
   - **With a passphrase:** enter your chosen passphrase and repeat it. The script may then ask you to unlock the key. In later sessions, unlock it when needed using:

     ```bash
     ssh-add ~/.ssh/id_ed25519
     ```

6. **Confirm the camera’s identity if prompted.** SSH may display a host fingerprint and ask whether to continue connecting. Compare it with the camera’s trusted fingerprint, then type **`yes`** and press **Enter** if it matches.

7. **Enter the camera’s SSH password when prompted.** The default password for the existing QUT camera is:

   ```text
   123456
   ```

   Use the current password if it has been changed. Nothing appears while typing. The script copies your public key to the camera so future connections can use the key instead of requesting the camera password each time.

8. **Wait for setup to finish.** The script checks that it can log in without requesting the camera password and read the camera’s temperature. It then reports that hardware setup is complete.

   If working SSH access already exists, the key creation and password steps are skipped.

Both scripts can be rerun. Hardware setup normally only needs repeating when the
adapter or SSH access changes. To repeat individual hardware steps:

```bash
bash src/stonefish_qut_rov/setup_scripts/setuphardware.sh --network   # Configure and activate Ethernet
bash src/stonefish_qut_rov/setup_scripts/setuphardware.sh --camera    # Set up SSH with Ethernet already active
```

This configures the laptop for the existing QUT vehicle; its MAVLink bridge must
already forward to `192.168.2.1:14550`. It does not flash or configure onboard firmware.


## Digital Twin simulation install

### 1. Prerequisites

Complete the real software and hardware stages above first. The DT installer
uses the same workspace and ROS 2 Jazzy installation. The real software stage is
required; simulation itself can run with the physical ROV disconnected afterward.

Stonefish requires a GPU and driver supporting **OpenGL 4.3 or newer**. Install
the appropriate driver using Ubuntu's Additional Drivers tool if necessary and
reboot. Run the simulator in a graphical desktop session. Connect a gamepad to
operate the simulated vehicle.

### 2. Run the automated DT installer

There is no second DT repository to clone. Open a fresh terminal outside any
Python virtual environment or Conda and run:

```bash
cd ~/Desktop/ROV_and_DT_ws
bash src/stonefish_qut_rov/setup_scripts/install_dt.sh
```

The script automatically:

- Installs the compiler/CMake tools, OpenGL development libraries, GLM, SDL2,
  FreeType, PCL, rosdep and Python virtual-environment tools.
- Downloads and builds the Stonefish C++ library in `.dependencies/stonefish`,
  installs it under `/usr/local`, and refreshes the shared-library cache.
- Downloads `stonefish_ros2` into `src/stonefish_ros2`, installs both ROS packages'
  declared dependencies using rosdep, and builds the wrapper and QUT DT package.
- Creates `venv-yellow-tang` with access to ROS system Python modules, installs
  the fish detector dependencies and runs a CPU inference check using the
  bundled `models/stonefish_yolo.pt` model. NumPy and OpenCV versions are constrained
  to avoid incompatibility with Ubuntu's ROS Python packages.
- Creates or refreshes the **ROV** desktop and applications-menu shortcut.

No simulator or physical control process starts during installation. The script
stops on an error; correct the reported problem and rerun the same command.
Downloads and compilation require internet, disk space and time. The default
build uses two compiler jobs; reduce this on a machine with limited RAM:

```bash
ROV_BUILD_JOBS=1 bash src/stonefish_qut_rov/setup_scripts/install_dt.sh
```

The installer pins both upstream projects to revisions declaring **1.6.0**:

| Component | Revision |
| --- | --- |
| Stonefish | `b21eb8e194c570ff2f61e91aeffb38d73dc25f42` |
| stonefish_ros2 | `6646e7ac25eed982f37f807abc7b545dbd2d6648` |

Keep these dependencies paired when upgrading. Existing checkouts at other
revisions or with tracked changes cause the installer to stop rather than
replace your work. Preserve them and move them aside before retrying. Stonefish
is installed system-wide under `/usr/local`, which can replace an older
installation there. GPU-accelerated PyTorch is optional; CPU inference is used
for the installation check.

The resulting workspace is:

```text
~/Desktop/ROV_and_DT_ws/
├── .dependencies/stonefish/          # Stonefish C++ source and build
├── src/
│   ├── stonefish_ros2/               # ROS 2 simulator wrapper
│   └── stonefish_qut_rov/
│       ├── setup_scripts/           # Software, hardware and DT installers
│       ├── ros_nodes/
│       ├── scenarios/
│       ├── models/
│       └── icons/
├── build/
├── install/
├── log/
└── venv-yellow-tang/                 # Fish detector environment
```

### 3. Verify the installation and start simulation

After the installer completes:

```bash
cd ~/Desktop/ROV_and_DT_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
glxinfo -B
ros2 pkg prefix stonefish_ros2
ros2 pkg prefix stonefish_qut_rov
```

Check that OpenGL is at least 4.3 and that both package prefixes point inside
this workspace's `install/` folder. Then double-click **ROV** on the desktop or
open **ROV** from the applications menu. If required, right-click the desktop
icon and select **Allow Launching**. Select a vehicle model, then choose
**Launch simulation**. The default `real_rov.scn` runs in the coral reef environment.

Terminal alternative for the graphical launcher:

```bash
cd ~/Desktop/ROV_and_DT_ws
bash src/stonefish_qut_rov/ros_nodes/common/launch_rov_gui.sh
```

Direct simulation control, without the GUI:

```bash
cd ~/Desktop/ROV_and_DT_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
source venv-yellow-tang/bin/activate
ros2 run stonefish_qut_rov rov_control.py --mode sim --rov-scenario real_rov.scn
```

The GUI activates the virtual environment automatically when launching control.
With a gamepad connected, **A** arms/disarms, **Y** opens the camera/detector and
**X** toggles fish following while the camera window is open. Use **Ctrl+C** in
the control terminal to stop the stack. See the controls figure above.

For a simulator-only check in the pool environment, run this instead of the full
control stack in a sourced terminal:

```bash
ros2 launch stonefish_qut_rov launch_rov.py environment:=pool_environment rov_scenario:=real_rov.scn
```

This starts only the simulator. Use `environment:=ocean_environment` for the reef.
Do not run it alongside the full simulation control stack.

## Use the physical ROV

Connect the tether and gamepad, power the ROV and camera, then open **ROV** and
select **Connect to real ROV**. Wait for Pixhawk connection, depth calibration
and camera readiness before operation. Disarm before shutdown; **Ctrl+C** in
the control terminal stops the stack. Run only one vehicle control stack at a time.

Hardware setup normally only needs repeating when the Ethernet adapter or
camera SSH access changes. The DT installation does not change those settings.

## Updates and troubleshooting

After source changes, rebuild from a new terminal:

```bash
cd ~/Desktop/ROV_and_DT_ws
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select stonefish_qut_rov --cmake-args -DBUILD_TESTING=OFF
source install/setup.bash
```

Rerun `install_software.sh` when real-mode dependencies change and `install_dt.sh`
when simulation dependencies change. Both are in `src/stonefish_qut_rov/setup_scripts`.
Neither installer updates existing Git checkouts automatically.

- **Desktop icon does not launch:** run `launch_rov_gui.sh` from the terminal as
  shown above to see the error. Refresh only the shortcut with
  `python3 src/stonefish_qut_rov/setup_scripts/create_shortcut.py`.
- **Workspace was moved:** move the generated `build/`, `install/` and `log/`
  folders aside, rerun the real installer, and then rerun the DT installer if
  using simulation. Recreate `venv-yellow-tang` after moving it because its
  scripts contain absolute paths. Do not delete source files or SSH keys.
- **No gamepad/depth/IMU:** check gamepad power and ROS topics in a sourced
  terminal: `ros2 topic list`, `ros2 topic echo /joy`, and
  `ros2 topic hz /qut_rov/imu`. Physical-mode MAVROS logs are in `/tmp/mavros.log`.
- **Video works but gimbal does not:** rerun the hardware script with `--camera`
  and unlock a protected SSH key with `ssh-add ~/.ssh/id_ed25519` if needed.
- **CMake cannot find Stonefish / version mismatch:** rerun the DT installer and
  check for another Stonefish installation in `CMAKE_PREFIX_PATH`.
- **`libStonefish.so` cannot be loaded:** check that installation completed and
  run `sudo ldconfig`.
- **Compiler killed:** retry the DT installer with `ROV_BUILD_JOBS=1`.
- **Simulator window fails:** inspect `glxinfo -B` and your graphics driver.
- **Fish detector fails:** activate `venv-yellow-tang`, verify the bundled model
  exists, and rerun the DT installer to restore dependency constraints. Do not
  use `sudo pip` to modify Ubuntu's system Python.

The installers check builds and Python imports; the DT installer also checks
model inference. Confirm graphical simulation and real hardware operation on
the target computer after installation. Automated setup-script checks can be run
without installing software or connecting a vehicle:

```bash
python3 src/stonefish_qut_rov/setup_scripts/test_setup.py
```
